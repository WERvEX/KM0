KM0 1.0：任务的分发不再只按档位，而是按公开榜单估计每个“Agent × 模型”组合的通过率，在你选的策略档位下挑期望成本最低的组合；拆完任务后可以在 KM0 里一键交给 KM0 Runner 执行，看着每个任务的进度，结束后自动验收。

## 新功能

- **模型能力数据**：从 SWE-bench、Terminal-Bench、SWE-Bench Pro、SWE-rebench、Aider、Artificial Analysis 和 Design Arena 的公开成绩估计每个模型在各类任务上的能力，以及每个 Agent 对本家模型和其他模型的加成。数据随 KM0 发布，每周更新，也可以在“设置 → Agent → 模型能力数据”里单独更新或从文件导入。
- **分发策略五档**：激进、偏省、平衡、偏稳、保守。越激进越省钱，越保守越看重质量；在达到目标首次通过率的组合里选期望成本最低的。项目可以设预算，超出时提示哪些任务降档后能放进去。路由表显示每个任务的难度、预计通过率（带区间）、期望成本，以及为什么没选更便宜的组合。
- **本地记录**：任务跑完后记一次通过或失败，KM0 Runner 的验收结论也会自动记下，用来修正模型的能力估计。记录只保存在本机，可以清除。
- **服务商与计费方式**：一个服务商对应一个地址和密钥，支持按 token、中转倍率、订阅（可填额度）和免费四种计费方式；模型按 ID 自动匹配到榜单数据，拿到官方价格和上下文窗口。
- **自定义 Agent**：除了内置的 Claude Code、Codex、Cursor、Pi、DSH、ZCode，可以添加自己的 Agent：项目说明文件、启动命令、能接的接口格式和本家模型厂商。条件相近时优先把模型交给它的本家 Agent（Claude 模型给 Claude Code，GPT 给 Codex，DeepSeek 给 DSH）。
- **一键执行**：在路由表下方点“执行”，KM0 先逐项检查（仓库、KM0 Runner、pi、密钥、预算），再生成 Runner 配置并启动它；每个任务的状态、模型、升档和花费实时显示，可以随时停止。结束后自动导入结果并验收，没通过的任务可以从更强的组合重做。也可以改用自定义命令执行（未验证）。需要 KM0 Runner 0.2.0 或更新的版本。
- **应用内更新**：“设置 → 关于”里检查、下载并重启安装新版本，启动时会自动检查（可以关掉）。
- **界面统一**：选择文件夹、导入和保存文件都在 KM0 自己的文件浏览器里完成，所有确认、提示和错误都用应用内的对话框和提示条，不再弹出系统对话框。

## 从 0.1 升级

- 第一次启动时 KM0 会先把数据库备份到同一个文件夹（`km0.db.before-5-….bak`），再升级。
- 原来的模型配置变成服务商和模型，密钥、角色和调用记录都保留；每个 Agent 按档位填写的模型变成它“能用的模型”，档位标签改为按能力自动划分，也可以在模型上手动指定。
- 原来的项目、文档、任务和手动调整都保留，按新的分发策略重新计算。
- 0.1 导出的配置文件仍然可以导入。

不想安装可以试网页调试版：<https://wervex.github.io/KM0/>，加 `?simulated=1` 用模拟模型，不需要 API Key。网页调试版不能启动本地程序，执行功能只在桌面版可用。

## 注意

- 安装包有没有签名取决于发布时是否配置了签名证书，本页末尾会写明。未签名时：
  - Windows 会弹出 SmartScreen 提示，点“更多信息 → 仍要运行”。
  - macOS 会提示“无法验证开发者”，在“系统设置 → 隐私与安全性”里点“仍要打开”，或右键应用选“打开”；未签名的 macOS 版本不能在应用内更新。
- Linux 的 AppImage 需要先 `chmod +x` 再运行；只有 AppImage 能在应用内更新。
- 订阅额度目前只统计 KM0 自己的调用，编码 Agent 的运行还没有计入。
- 在 Windows 上执行还没有实际验证过。
