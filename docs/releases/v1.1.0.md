KM0 1.1：除了交给 KM0 Runner 执行，现在也可以在 KM0 里把拆好的任务直接交给对应的编码 Agent（Claude Code、Claude Desktop、Codex）执行——每个任务在独立的 git worktree 和分支里完成，自动提交改动、运行测试并进入同一套验收流程。

## 新功能

- **直接交给 Agent 执行**：“设置 → 执行”新增第三种执行方式“直接交给 Agent”，与 KM0 Runner、自定义命令并列。KM0 按任务依赖顺序为每个任务在运行目录下创建独立的 git worktree 和 `km0/<run_id>/<编号>` 分支（有多个上游依赖时自动依次合并，冲突则标为“阻塞”），不改动你当前的工作区和分支。Agent 结束后由 KM0 提交改动、运行任务的测试命令并写出与 KM0 Runner 同格式的报告，进度面板、停止、自动导入、规划模型验收、本地能力记录和“从更强的组合重做”完全通用。
- **Claude Code 直接执行**：自动调用 `claude -p --output-format stream-json --verbose --permission-mode acceptEdits`，按路由选定的模型和项目剩余预算全自动执行。工具调用实时计步并以相对 worktree 的路径显示在输出日志中；服务商配置了 API Key 或地址时通过环境变量传入，未配置时使用本机 Claude Code 自己的登录；Windows 下支持 `.cmd` 启动并在停止时结束整个进程树。
- **Claude Desktop 领任务（MCP）**：新增预置 Agent“Claude Desktop”（在“设置 → Agent”中启用后，可在路由表里将任务指定给它）。KM0 内置独立的 MCP 服务器（`km0-mcp.cjs`），“设置 → 执行”提供可一键复制的 `claude_desktop_config.json` 配置片段（交互式 Claude Code 也可通过 `claude mcp add` 接入）。执行到该任务时状态显示为“等待领取”，在 Claude Desktop 中说“做 KM0 的任务”，即可通过 `km0_next_task` 领取，并用严格限制在该任务 worktree 内的文件与测试工具（`km0_list_files`、`km0_read_file`、`km0_write_file`、`km0_delete_file`、`km0_run_tests`）完成修改后调用 `km0_report` 回报。
- **Codex 直接执行**：自动调用 `codex exec --json --sandbox workspace-write --model <模型> -` 在任务 worktree 内执行（需要 Codex CLI 0.100.0 或更新），工具调用和 token 用量实时记录，结束后由 KM0 提交改动并运行测试。
- **逐任务升级链（KM0 Runner 0.3.0）**：为每个分到模型的任务生成独立的升级阶梯（`task_ladders`），配合 KM0 Runner 0.3.0 或更新版本按任务自身的升级链升档。
- **应用内更新与界面改进**：
  - 新增真实打包程序的应用内更新端到端测试（Linux AppImage 与 Windows NSIS）；修复 Windows 应用内更新会弹出安装向导的问题，改为静默安装并自动重启 KM0。
  - 修复双滚动条问题：主窗口不再自身滚动，项目内容区与右侧决策账本独立滚动，并使用适配主题色的细滚动条。
  - 执行面板改进：运行日志占满整行宽度，Claude Code 与 Codex 的工具调用统一显示相对 worktree 的路径与搜索词；小于 $0.01 的花费统一精确显示到小数点后 4 位（如 `$0.0052`）；执行前预检只检查本次运行实际用到的 Agent。

## 下载

| 平台 | 文件 |
| --- | --- |
| Windows (x64) | `KM0-1.1.0-setup-x64.exe` |
| macOS (Apple 芯片) | `KM0-1.1.0-arm64.dmg` |
| macOS (Intel) | `KM0-1.1.0-x64.dmg` |
| Linux (x64) | `KM0-1.1.0-x86_64.AppImage` |

不想安装可以试网页调试版：<https://wervex.github.io/KM0/>，加 `?simulated=1` 用模拟模型，不需要 API Key。网页调试版不能启动本地程序，执行功能只在桌面版可用。

## 注意

- 安装包有没有签名取决于发布时是否配置了签名证书，本页末尾会写明。未签名时：
  - Windows 会弹出 SmartScreen 提示，点“更多信息 → 仍要运行”。
  - macOS 会提示“无法验证开发者”，在“系统设置 → 隐私与安全性”里点“仍要打开”，或右键应用选“打开”；未签名的 macOS 版本不能在应用内更新。
- Linux 的 AppImage 需要先 `chmod +x` 再运行；只有 AppImage 能在应用内更新。
- 订阅额度目前只统计 KM0 自己的调用，编码 Agent 的运行还没有计入。
