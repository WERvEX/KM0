KM0 1.2：面向已有仓库的快速规划、跨 Agent 结构化交接与即时验收门禁、以及基于任务依赖图（DAG）的并行执行与最终集成分支整合。现在多个编码 Agent（Claude Code、Codex、Claude Desktop）可以在同一项目中自动并行分工、互相传递接口契约、自动解决合并冲突，并汇总为可一键审查与合并的集成分支。

## 新功能

- **已有项目快速规划与深度仓库扫描**：
  - 关联本地仓库时深度扫描模块目录结构、可运行脚本（`dev` / `build` / `test` / `lint` 等）和仓库规范文档（`CLAUDE.md`、`AGENTS.md`、`.cursorrules`、`CONTRIBUTING.md` 等），自动预填架构模块与测试策略，避免重复问答。
  - 新建任务支持「快速规划已有项目」模式：基于仓库扫描结果走轻量直达通道，聚焦具体改动边界并直接生成面向现有代码目录的任务拆解（附带涉及文件与最小验证命令）。
- **跨 Agent 结构化交接（Handoff Notes）**：
  - 每个任务完成后自动从统一 diff 提取新增/修改的导出签名（TypeScript/JavaScript、Python、Go、Rust 等）与 Agent 回报的契约及下游注意事项，保存至 `handoffs/<NN>.json`，并在下游任务启动时写入工作区的 `km0/upstream.md` 与任务提示词顶部（`km0/` 不会提交进代码分支）。
  - Claude Desktop 的 MCP 工具 `km0_report` 同步支持上报 `contracts` 与 `downstream_notes`，跨 Agent 协作上下游衔接更准确。
- **逐任务即时 EARS 验收门禁、原地修补与跨 Agent 自动升档**：
  - “设置 → 执行”新增「每完成一个任务立即用规划模型验收」与「修补仍未通过或出错时，沿升级链自动换更强的组合重做」开关（均默认开启）。
  - 在解锁下游任务前，KM0 即时调用规划模型对照 EARS 验收标准判定；未通过测试或验收时先将精确失败反馈送回当前 worktree 进行原地修补（`KM0_REPAIR`），仍未通过则重置干净基线并沿任务升级链自动切换至更强组合（支持跨 Claude Code / Codex 升级），结束后直接复用已有验收结论避免重复调用模型。
- **DAG 并行调度与多分支合并冲突自动协调**：
  - 直接执行引擎升级为动态 DAG 调度器，无相互依赖的任务在独立 `git worktree` 中并行运行；“设置 → 执行”可配置「最大并行任务数（1–6，默认 3）」，并发停止时同步中止所有在途 Agent 并清理全部 worktree。
  - 新增「多分支合并冲突时自动交给 Agent 协调解决」开关（默认开启）：当多上游或并行分支改动同一文件触发 git 冲突时，自动委派最强可用 CLI Agent 结合冲突各方交接契约解决冲突，并严格校验无残留冲突标记后完成合并提交；未能干净解决时自动中止合并保持仓库整洁。
- **最终集成分支与一键集成 UI**：
  - 全部任务完成后自动整合所有末端分支生成 `km0/<run_id>/final` 与全量 `diffs/final.diff`（如仓库配置了测试命令则在集成分支上执行验证）。
  - 执行面板的任务卡新增集成分支状态条，支持 **总 Diff** 弹窗审查、**合并到当前分支** 与 **检出分支**（工作区有未提交改动或合并遇冲突时均安全拦截/自动中止，绝不污染工作区）。

## 下载

| 平台 | 文件 |
| --- | --- |
| Windows (x64) | `KM0-1.2.0-setup-x64.exe` |
| macOS (Apple 芯片) | `KM0-1.2.0-arm64.dmg` |
| macOS (Intel) | `KM0-1.2.0-x64.dmg` |
| Linux (x64) | `KM0-1.2.0-x86_64.AppImage` |

不想安装可以试网页调试版：<https://wervex.github.io/KM0/>，加 `?simulated=1` 用模拟模型，不需要 API Key。网页调试版不能启动本地程序，执行功能只在桌面版可用。

## 注意

- 安装包有没有签名取决于发布时是否配置了签名证书，本页末尾会写明。未签名时：
  - Windows 会弹出 SmartScreen 提示，点“更多信息 → 仍要运行”。
  - macOS 会提示“无法验证开发者”，在“系统设置 → 隐私与安全性”里点“仍要打开”，或右键应用选“打开”；未签名的 macOS 版本不能在应用内更新。
- Linux 的 AppImage 需要先 `chmod +x` 再运行；只有 AppImage 能在应用内更新。
- 订阅额度目前只统计 KM0 自己的调用，编码 Agent 的运行还没有计入。
